# Спецификация: `local.session-tree` — проекты и треды в сайдбаре OpenCode TUI

| | |
|---|---|
| Версия | 0.4 (проекты внутри структуры OpenCode, полная зачистка, мышь) |
| Дата | 15.11.2026 |
| Целевая платформа | OpenCode v2.0.32+, TUI-плагин (`@opencode/plugin/tui`) |
| Тип поставки | локальный плагин: TUI-часть + серверная часть (RPC) |
| Статус | к реализации P0 |

## 01. Задача

Правая панель TUI в полноэкранном терминале показывает служебный блок: контекст в токенах, процент использования, подключённые MCP-серверы. Навигации по проектам и тредам нет — только `/sessions`, табы и история.

Нужно добавить **под штатным блоком, через разделитель**, дерево, работающее в **одном окне терминала**:

```
ПРОЕКТЫ                                          2
▾ acme                                          2
  › auth-refactor                    ●   [активен]
  · billing-fix                      ○
▸ internal-tools                                1
  · migrate-ci                       ○

БЕЗ ПРОЕКТА                                      1
  · scratch-session                  ○
```

Плюс управление: открыть, создать тред, переименовать, удалить, свернуть, закрепить — мышью и с клавиатуры.

## 02. Решения (ответы заказчика)

| # | Вопрос | Решение |
|---|---|---|
| 1 | Что такое проект | Папка проекта, в которой работает агент. Внутри — свободно; вне — только по прямому разрешению, папка проекта приоритетна |
| 2 | Контекст тредов | Каждый тред получает **свою подпапку** внутри проекта — отдельный рабочий каталог, контексты не смешиваются |
| 3 | Каталог тредов | **Видимый, валидный каталог** `threads/` в корне проекта (не скрытый) |
| 4 | Структура дерева | `Проект → список тредов проекта`; отдельно секция **«Без проекта»** для тредов вне зарегистрированных проектов |
| 5 | Открытие треда | Всегда в **текущем окне** терминала, без каскада окон и новых табов |
| 6 | Удаление треда | Полное: сессия и контекст стираются безвозвратно (после подтверждения) |
| 7 | Сабагенты | По флагу, по умолчанию выключены |
| 8 | ПКМ | Универсально: мышь + клавиатура, полный паритет |
| 9 | Удалённый сервер | Нужен на перспективу — этап P2 |
| 10 | Где живут проекты | Автоматически в структуре OpenCode: `~/.local/share/opencode/projects/<проект>/threads/<тред>/`; ручная привязка к папке не нужна |
| 11 | Удаление проекта | Полная зачистка: все сессии и сабагенты проекта, история, папка с тредами и временными файлами |
| 12 | Мышь | Штатные обработчики OpenTUI: левый клик — открыть/развернуть, правый — меню; «+» в заголовке секции и у проекта |

## 03. Цели и не-цели

**Цели**
1. Навигация «проект → тред» + «без проекта» в одном окне.
2. Тред = сессия + собственная видимая подпапка в `threads/`.
3. Создание, переименование, удаление тредов; свёртывание/закрепление проектов.
4. Полный паритет мыши и клавиатуры.
5. Состояние дерева переживает перезапуски.
6. Никаких изменений в бинаре OpenCode; отключение одной строкой.

**Не-цели**
1. Не управляем содержимым проекта за пределами каталога тредов (файлы проекта плагин не трогает).
2. Не расширяем права агента: выход за папку проекта — по `permissions`, не по воле плагина.
3. Не форкаем OpenCode и не стилизуем «host»-узлы сайдбара.
4. Не заменяем табы и `/sessions`.
5. P0/P1 — только локальный сервер; удалённый — P2.

## 04. UX

### 4.1 Размещение и вид

- Слот: `context.ui.slot({ append: "sidebar.content", render })` — после штатного блока, с тонким разделителем.
- Видимость зависит от сайдбара (`cli.json → session.sidebar`: `auto`/`hide`). В узком терминале панель скрыта хостом — все действия остаются в палитре и слэш-командах.
- Две секции: `ПРОЕКТЫ` и `БЕЗ ПРОЕКТА`. Секция «Без проекта» показывается, только если такие треды есть; свёртывается отдельно.
- Проект: `▸/▾ <имя> · <N>`; тред: `· <заголовок>`, активный — `›` + акцент; статусы: `●` выполняется, `○` ожидает, `!` ошибка/разрешение.
- Сабагенты (при флаге): вложены с отступом, серые, без действий изменения.
- Пустые состояния: `Нет проектов` + `n — создать тред в текущей папке`; для «Без проекта» — `Создаст тред в текущей папке (без проекта)`.
- Лимиты отрисовки: 20 проектов, 30 тредов на секцию/проект, далее `… ещё N`.

### 4.2 Одно окно

- Открытие треда = `router.navigate({ type: "session", sessionID })` в текущем окне. Плагин не открывает табы и окна.
- Переключение проекта не меняет окно — меняется содержимое панели; открывается выбранный тред.

### 4.3 Клавиатура (при фокусе в панели; вне фокуса — палитра)

| Клавиша | Действие |
|---|---|
| `↓` / `↑` | Перемещение по строкам |
| `→` / `←` / `space` | Развернуть / свернуть проект или секцию |
| `Enter` | Открыть тред (для проекта/секции — развернуть) |
| `n` | Новый тред (в проекте; в секции «Без проекта» — в текущей папке) |
| `r` | Переименовать тред / алиас проекта |
| `d` | Удалить тред (подтверждение) |
| `p` | Закрепить/открепить проект |
| `s` | Показать/скрыть сабагентов |
| `/` | Фильтр по имени/пути (P1) |
| `Esc` | Снять фильтр / выйти из панели |

Все действия дублируются командами палитры `session-tree.*` и слэш-командами.

### 4.4 Мышь

- Левый клик по проекту/секции — развернуть/свернуть; по треду — выделить; двойной клик или Enter — открыть.
- Правый клик — контекстное меню (overlay у курсора):
  - Тред: `Открыть`, `Переименовать`, `Копировать ID`, `Удалить`.
  - Тред «без проекта»: `Открыть`, `Переименовать`, `Копировать ID`, `Удалить`, `Привязать к проекту` (P2).
  - Проект: `Новый тред`, `Переименовать (алиас)`, `Закрепить`, `Свернуть`, `Скопировать путь`, `Скрыть из дерева`.
- `Esc`/клик вне меню — закрыть. Мышь — на собственных renderable плагина; при недоступности мышиных событий клавиатурный путь остаётся полным.

### 4.5 Диалоги

- Создание: без модала, имя генерируется, сразу открывается.
- Переименование: `ui.dialog.prompt`, лимит 80 символов, пустое отклоняется.
- Удаление: `ui.dialog.confirm` с путём папки и предупреждением «сессия и папка будут удалены безвозвратно»; кнопка подтверждения не дефолтная.
- Ошибка: `ui.toast.show({ variant: "error" })`, состояние строки не меняется.

## 05. Модель данных

### 5.1 Соответствие сущностям OpenCode

| Понятие | Источник |
|---|---|
| Проект | корневая папка (location), зарегистрированная в плагине |
| Тред проекта | корневая сессия (`session.root(id) === id`), location = `<project>/threads/<slug>` |
| Тред «без проекта» | корневая сессия, чей location не входит ни в один зарегистрированный проект |
| Сабагент | дочерняя сессия (`session.family(rootID)`) |
| Заголовок / статус | `session.get(id).title` / `session.status(id)` |

**Важно:** OpenCode считает каждую папку отдельным location/проектом. Плагин группирует location'ы: карта `roots[threadFolder] = projectRoot`; сессии вне карты попадают в секцию «Без проекта». Дерево строится по корням, а не по «сырым» проектам OpenCode.

### 5.2 Раскладка на диске (v0.4)

Проекты создаются плагином автоматически внутри структуры OpenCode — привязка к папке не требуется:

```
~/.local/share/opencode/projects/    ← корень проектов (опция projectsRoot)
├── acme/                            ← проект (создаётся «+» или /tree-project-new)
│   └── threads/                     ← видимый каталог тредов проекта
│       ├── auth-refactor/           ← тред: рабочий каталог агента
│       │   └── .session-tree-thread.json   ← маркер владения
│       └── billing-fix/
└── internal-tools/
```

- Имя проекта = имя папки (1–60 символов, без `/`, `\`, `:`, не начинается с точки).
- Маркер `.session-tree-thread.json`: `{ "schema": 1, "sessionID": "...", "createdAt": "..." }` — плагин удаляет только папки со своим маркером.
- **Переименование проекта** = `fs.rename` папки + `session.move` для всех сессий проекта (привязка перепрыгивает на новый путь автоматически).
- **Удаление проекта** = `session.remove` для всех сессий (рекурсивно удаляет сабагентов и историю) + `rm -rf` папки проекта. Необратимо, требует подтверждения.
- Если `threads/` проекта содержит чужие папки без маркеров — создание треда не пишет в него (ошибка `occupied`).

### 5.3 Локальное состояние плагина

`context.storage.store("session-tree", { initial })`:

```jsonc
{
  "schemaVersion": 1,
  "roots":    { "<projectRoot>": { "alias": "acme", "pinned": true, "collapsed": false } },
  "threads":  { "<threadFolder>": { "root": "<projectRoot>|null", "sessionID": "ses_...", "slug": "auth-refactor" } },
  "hidden":   ["<projectRoot>"],
  "order":    ["<projectRoot>"],
  "prefs":    { "showSubagents": false, "mouseMenu": true, "threadDir": "threads", "threadNaming": "slug" }
}
```

`"root": null` в `threads` — тред «без проекта». Миграции — по `schemaVersion`, без сброса.

**Порядок проектов (v0.8)** хранится не в storage, а отдельным файлом рядом с проектами —
его пишет серверная часть, потому что порядок нужен `buildTree` на сервере:

```jsonc
// <projectsRoot>/.session-tree-order.json
{ "schema": 1, "projects": ["Bug Bounty — AlfaBit", "Картечь — Red Team"] }
```

Правило: имена из `projects` — в заданном порядке, остальные — следом по алфавиту. Запись
атомарная (`tmp` + rename), неизвестные имена при чтении игнорируются, переименование проекта
переносит запись на новое имя, удаление — вычищает.

## 06. Архитектура

```
~/.config/opencode/plugins/session-tree/
├── package.json      // exports: { ".": "./server.ts", "./tui": "./tui.tsx", "./rpc": "./rpc.ts" }
├── rpc.ts            // контракт: createThread, renameThread, deleteThread, listTree, adoptThread (P2)
├── server.ts         // файловые операции + создание/удаление сессии
├── tui.tsx           // Plugin.define({ id: "local.session-tree", setup })
├── src/{state.ts,actions.ts,Tree.tsx,Menu.tsx}
└── SPEC.md
```

**Почему две части.** Файловые операции выполняются там, где лежит проект, — в процессе сервера OpenCode. TUI-часть только рисует и вызывает RPC. Это же даёт путь к P2 (удалённый сервер: TUI подключается к нему, папки создаются на его хосте).

### 6.1 Точки API

TUI-часть (документировано): `ui.slot("sidebar.content")`, `data.project/session.*`, `ui.router.navigate`, `ui.dialog.*`, `ui.toast.show`, `keymap.layer`, `storage.store/memory`, `theme`, `ui.format.path`, `client`.

Серверная часть: RPC `listTree/createProject/renameProject/deleteProject/reorderProject/createThread/deleteThread/renameThread/deleteSession/moveThread/createLoose` (+ `adoptThread` в P2); файловые операции через Node/Bun API в процессе сервера.

> Шаг 0 перед кодом: сверить по `/openapi.json` и `build/plugins/server` точные имена `client.session.*`, схему создания сессии с `location`, форму RPC-контракта. До сверки — контрактные зависимости.

**Сверка выполнена (2.0.32), найденные особенности:**
- HTTP-конверт RPC: запрос `{"input": {...}}`, ответ `{"output": {...}}` (эндпоинт `/api/rpc/<id>/<method>`).
- У RPC-метода **обязательна** схема `input` — метод без `input` падает в рантайме (`"~standard" in undefined`), даже если схема не нужна (пустой объект `{"type":"object","additionalProperties":false}` решает).
- `session.create` принимает `location: { directory }` — сессия сразу привязывается к папке треда.
- `session.move({sessionID, directory})` доступен для P2 (`adoptThread`).

### 6.2 Поток данных

1. `setup`: подписка `data.listen`, `project.sync()` + `session.sync()`.
2. Дерево: `roots` из storage + `project.list()`/`session.list()`; location'ы сворачиваются в корни; remainder → «Без проекта».
3. Действие → RPC → `invalidate/sync` → точечный ререндер.
4. Cleanup: отписки, снятие слоя keymap, без таймеров после выгрузки.

## 07. Поведение

**Создание треда в проекте**
1. Слаг `^[a-z0-9-]{1,40}$`; коллизии → `-2`, `-3`.
2. Сервер: `mkdir <projectRoot>/threads/<slug>` + маркер + сессия с этим location.
3. Открытие в текущем окне, проект разворачивается.

**Создание треда «без проекта»**
- В текущей папке запуска плагина: сессия создаётся без подпапки (location = текущий каталог), попадает в секцию «Без проекта». Подпапки для неё не создаются, чтобы не мусорить вне проектов.

**Переименование**
- Тред: меняется заголовок сессии. Папка и слаг не переименовываются — путь стабилен.
- Проект: меняется алиас в storage.

**Удаление**
1. Подтверждение с полным путём папки.
2. Сервер: удаление сессии, затем `rm -r` папки **только** при маркере и нахождении внутри `<projectRoot>/threads/`.
3. Тред «без проекта»: удаляется только сессия (подпапки нет).
4. Отказ (нет маркера / путь вне threads/ / папка = корень проекта) → удаляется только сессия, папка остаётся, тост с причиной.
5. После удаления фокус на соседний тред, иначе `home`.

**Прочее**
- Сортировка проектов: сначала порядок из `<projectsRoot>/.session-tree-order.json` (задаётся
  перетаскиванием), затем всё, чего в списке нет, — по алфавиту в конце. Переименование
  переносит запись на новое имя, удаление — вычищает. Для тредов внутри проекта порядок пока
  файловый (`readdir`).
- Треды «Без проекта» — по активности.
- Ошибки сети: строка `!`, локальное состояние не меняется без подтверждения сервера.
- Гонки: одна операция на тред, повторный клик игнорируется.

## 08. Производительность

- Первый рендер < 200 мс при 50 проектах × 30 тредах (`--standalone`).
- Никаких сетевых вызовов на кадр; `sync()` — по событию/открытию панели.
- Мемоизация строк по `(id, title, status, updatedAt)`; лимиты вместо полного списка.
- Обход дефекта ядра (#59458 — слот не ререндерится на реактивные обновления): собственные сигналы + явный `invalidate()`; проверка в приёмке.

## 09. Ограничения и риски

| Риск | Влияние | Мера |
|---|---|---|
| Рекурсивное удаление папки | Потеря файлов | Только при маркере, только внутри `threads/`, подтверждение с путём, без симлинков |
| `threads/` уже занят в проекте | Конфликт с существующим кодом | Проверка при регистрации проекта; альтернативный каталог по подтверждению |
| Видимый каталог в git | Мусор/шум в репозитории | Решение владельца; плагин не правит `.gitignore`, пояснение в README |
| Host renderables не API | Стили сайдбара меняются в релизах | Только слот, без вмешательства в чужие узлы |
| Мышь не документирована | ПКМ может сломаться после апдейта | Клавиатурный паритет обязателен; мышь за флагом `mouseMenu` |
| Дефект реактивности слота (#59458) | Дерево «застревает» | Свои сигналы + `invalidate/sync`, тест |
| Папка треда = отдельный location | Дубли в `/sessions` вне плагина | Группировка по `roots`, пояснение в README |
| Сайдбар скрыт в узком терминале | Панель не видна | Действия в палитре/слэше |
| Конфликт хоткеев | Перехват глобальных клавиш | `keymap.layer` с `target` на панели, низкий приоритет |

## 10. Совместимость и обновления

- Требования: OpenCode `>= 2.0.32`, `@opencode/plugin` latest; peer `@opentui/core >= 0.6.6`, `@opentui/solid >= 0.6.6`, `solid-js >= 1.9`.
- Плагин вне бинаря: обновление OpenCode не снимает и не ломает установку.
- Подключение: `opencode.json → plugins: ["local.session-tree"]`; отключение — `"-local.session-tree"` или `opencode plugin remove`.
- Перед апдейтом: прогон `opencode --standalone` с плагином и без.
- Критерий устойчивости: сломанный плагин не блокирует запуск TUI.

## 11. Безопасность

- Плагин не выполняет shell-команды и не читает содержимое файлов проекта.
- Файловые операции: `mkdir` в `<projectRoot>/threads/` и `rm -r` только по маркеру владения.
- Запрещено: трогать корень проекта, выходить за каталог тредов, следовать симлинкам при удалении.
- Права агента не расширяются: работа вне проекта — по `permissions` (`external_directory` и т.п.).
- Storage не содержит секретов, только алиасы, флаги и пути.
- Заголовки сессий — недоверенный текст, не исполняется и не интерпретируется как разметка.

## 12. Приёмка

**Функциональные**
- [ ] Панель под штатным блоком, отделена разделителем; секции «Проекты» и «Без проекта».
- [ ] Клик по проекту разворачивает список тредов.
- [ ] Открытие треда — в текущем окне, без новых табов и окон.
- [ ] Новый тред создаёт видимую подпапку `threads/<slug>/` и сессию, сразу открывается.
- [ ] Тред «без проекта» создаётся без подпапки и виден в своей секции.
- [ ] Переименование меняет заголовок; папка не переименовывается.
- [ ] Удаление стирает сессию и подпапку после подтверждения; отмена ничего не меняет.
- [ ] Удаление папки без маркера не происходит (только сессия).
- [ ] Занятый `threads/` не перезаписывается; предлагается альтернатива.
- [ ] Свёрнутость, закрепление, алиасы, флаг сабагентов сохраняются после перезапуска.
- [ ] ПКМ-меню и клавиатура дают одинаковый набор действий.

**Нефункциональные**
- [ ] 50×30 без заметных лагов; первый рендер < 200 мс.
- [ ] Нет ошибок в логе `role=cli` при старте и выгрузке.
- [ ] Отключение одной строкой возвращает штатный TUI.
- [ ] `opencode --standalone` запускается с плагином и без него одинаково.
- [ ] После перезапуска сервера дерево восстанавливается из storage + API.

**Тест-план**
1. Пустое состояние: нет проектов → `n` создаёт тред в текущей папке (секция «Без проекта»).
2. Проект без тредов → создание и открытие; каталог `threads/` появляется.
3. `threads/` уже существует с чужими файлами → подтверждение/альтернатива, ничего не перезаписано.
4. Два треда → переключение в одном окне, контексты не смешиваются.
5. Удаление активного треда → фокус на соседа.
6. Папка треда без маркера → удаляется только сессия.
7. Два TUI-инстанса → изменения дерева синхронизируются.
8. Узкий терминал → панель скрыта, действия через палитру.
9. Остановленный сервер → тост, локальное состояние не расходится.

## 14. Остаточные вопросы (не блокируют P0)

1. Имя папки треда: чистый слаг (по умолчанию) или `дата-слаг` — сделать переключателем в настройках?
